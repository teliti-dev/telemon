# Aturan repo

Repo publik (AGPL-3.0), satu branch: `master`. Jangan menulis detail infrastruktur pribadi, alamat internal, atau rahasia di kode, komentar, commit, maupun dokumen.

1. Perubahan perilaku harus disertai tes dan pembaruan README atau komentar yang terdampak.
2. Pesan commit dan PR tanpa atribusi Claude.
3. Teks tampilan dua bahasa (id/en): jalankan `bun run i18n:check`.

## Struktur dan perintah
Aplikasi desktop **Tauri v2** (Windows dan Linux, tanpa deploy).
- Akar repo: UI React (Vite + TypeScript + shadcn/ui), dikelola dengan **bun**. Fokus tahap awal: UI dengan data contoh, poller menyusul. **Wajib responsif mobile** karena bisa dibuka dari HP lewat mode serve (tabel jadi kartu di lebar kecil, sidebar jadi sheet).
  - `bun install`, `bun run dev` (UI saja di browser), `bun run build`, `bun run lint`, `bun run typecheck` (`tsc -b`).
  - Komponen shadcn: `bunx --bun shadcn@latest add <komponen>`.
- `src-tauri/`: core Rust (poller RouterOS, SQLite, command/event Tauri). `bun run tauri dev`, `bun run tauri build`.
- Mode **"Serve ke browser"**: tombol di UI menyalakan server Axum di proses yang sama (bawaan mati; LAN port 7878; login akun wajib; hanya baca) yang menyajikan UI yang sama + API JSON dan WebSocket. UI memakai satu lapisan data dengan adapter Tauri dan HTTP; setiap fitur data harus tersedia di keduanya.
- Mode **"Publik"**: Cloudflare Quick Tunnel lewat sidecar `cloudflared` (versi dikunci + checksum) ke server mode serve. Wajib login akun + 2FA, hanya baca, rate limit login, mati otomatis (bawaan 8 jam). Event live via **WebSocket + cadangan polling, jangan SSE** (Quick Tunnel tidak mendukung SSE). Lihat ADR 0003.
- Crate Rust biasa dibangun dan diuji tanpa dependensi sistem Tauri (`cd crates/telemon-core && cargo test`); build `src-tauri` butuh WebKitGTK dan dibangun oleh CI rilis.
- **Edit user = catatan lokal** (`UserMeta`: nama pelanggan, telepon, label, catatan; disimpan di SQLite Telemon, kunci `routerId:username`). Tidak menulis ke router. Di mode serve/publik (adapter HTTP) catatan hanya bisa dibaca.
- **Mikrotik source of truth** (ADR 0004). Import (`importFromRouter`) menimpa salinan Telemon dengan data router; yang hilang di router ditandai soft delete. Tulis ke router hanya `/ppp/secret` dan `/ppp/profile`: langsung saat simpan setelah dialog tinjau, hanya untuk router `canWrite` yang online, dan hanya dari aplikasi desktop (adapter HTTP/serve/publik menolak semua tulis dan import). Jangan pernah memanggil `remove` pada secret/profile router: hapus = soft delete (secret di-disable, sesi diputus; profile hanya ditandai di Telemon dan ditolak bila masih dipakai). Password PPPoE tampil di detail user hanya untuk izin Ubah (tersembunyi bawaan, ADR 0009; menggantikan "write-only" ADR 0004); jangan dicatat di log. Fitur tulis lain butuh ADR baru.
- Kredensial router di keyring OS, bukan di SQLite atau berkas.

## Struktur UI (`src/`)
- `lib/data/api.ts`: kontrak `TelemonApi` (snapshot + live update + aksi). Adapter: `mock.ts` (data contoh, dipakai sekarang); adapter Tauri dan HTTP menyusul.
- `lib/store.tsx` + `lib/store-context.ts`: state global (router, user, event, share) dari adapter.
- `lib/route.ts`: routing hash (`#/user?status=active`), sama di Tauri dan mode serve.
- `pages/`: ringkasan, user, profile, event, router, berbagi. Users dan Profile satu menu sidebar (segmen di atas halaman); sidebar tetap 5 menu. `components/status.tsx`: label/ikon status dan event.
- Penanda **terpilih** (menu aktif atas/bawah, toggle, tab, pilihan di drawer) hanya mengubah warna ikon dan teks ke `text-brand` (biru, token `--brand`, kontras 6,8:1 terang dan 7,2:1 gelap), **tanpa mengubah latar**. Jangan memakai warna status untuk pilihan.
- Drawer/sheet **penuh layar di HP**: beri `data-[side=right]:w-full` (bukan `w-full` biasa, yang kalah oleh `data-[side=right]:w-3/4` bawaan) dan padding area aman; di layar ≥ 640 px lebarnya dibatasi `max-w-sm` bawaan.
- Filter di HP dipadatkan jadi dropdown dalam satu baris (`components/filter-select.tsx`: `FilterSelect`, `FilterMulti`); chip hanya di desktop. Tombol dropdown menampilkan nama filter (redup) saat bawaan dan nilainya (brand) saat aktif.
- Warna status (`--status-good|warning|serious|critical` di `index.css`) hanya untuk titik/ikon, selalu dengan label; teks memakai token teks.
- Header dua baris (`components/site-header.tsx`): logo + Live + Appearance + Profile, lalu menu utama di bawahnya (garis bawah pada menu aktif). Lebar dan jarak kiri-kanan konten satu sumber di `lib/layout.ts` (`PAGE_CONTAINER`, maks 7xl); pakai itu untuk elemen halaman baru.
- Navigasi: **menu atas** di desktop dan **menu bawah** di HP (< 768px, `components/bottom-nav.tsx`); tidak ada sidebar. Daftar menu dan angka lencana satu sumber (`components/nav-items.ts`, `hooks/use-nav-badges.ts`); Berbagi (hanya desktop), Admin, dan Pengaturan tampil di kanan menu atas sesuai izin; di HP masuk "Lainnya" pada menu bawah. Halaman memberi ruang bawah untuk menu itu (`pb-[calc(4.5rem+env(safe-area-inset-bottom))]`).
- Kepadatan: kontrol (`Button`, `Input`, `Select`, `Toggle`, `Tabs`) 36 px di HP dan 28 px di md ke atas. Pakai varian `md:` bila menambah kontrol baru, jangan mengecilkan di HP (area ketuk). **Jangan mengubah font-size root** (`html`): hampir semua ukuran Tailwind berbasis `rem`, jadi jarak, tinggi kontrol, dan ikon ikut menyusut (pernah membuat UI terlalu kecil). Tema dan ukuran tampilan (90-125%, `lib/ui-scale.ts`) diatur pengguna lewat drawer **Appearance** di kanan (`components/appearance-drawer.tsx`).
- **Dua mode akses** (`lib/access.ts`, ADR 0005): `desktop` (Tauri; tanpa login, boleh menulis ke router) dan `remote` (browser lewat serve/publik; wajib login, hanya baca). Pakai `useStore().access`, jangan `api.kind`, untuk membedakan keduanya. `components/auth-gate.tsx` memasang login di mode `remote`.
- Akun jarak jauh: login + 2FA TOTP + kode pemulihan, halaman Akun saya (`pages/account.tsx`). **Peran kustom dengan izin per menu** (ADR 0006): tiap menu (Ringkasan, Users, Profil PPP, Event, Router, Admin, Pengaturan) dicentang **Lihat** dan/atau **Ubah** (bawaan tanpa akses; Ubah mencakup Lihat; menu tanpa fitur ubah hanya punya Lihat); `lib/permissions.ts` (daftar menu, label, `pageDenied`), `hooks/use-write-gate.ts` (`useUpdateGate(resource)`, `useWriteGate(resource)` untuk izin + syarat router). Jangan membandingkan `access` langsung untuk izin tulis; pakai gate itu. Server harus menegakkan izin di setiap rute; UI hanya menyembunyikan dan menjelaskan.
- Istilah: **Profil PPP** = profile di router (`/ppp/profile`); **Akun saya** = profil sendiri akun jarak jauh (tanpa izin). Jangan menyebut keduanya "Profile".
- **Jarak jauh boleh edit dan tambah sesuai peran**, termasuk Router (tambah/edit/hapus), Admin, dan Pengaturan; yang tetap **hanya desktop**: Berbagi (serve/publik) dan izin tulis lewat publik. Pengaman anti-kenaikan izin (izin tidak melebihi milik sendiri, tidak mengubah akun/peran sendiri, tidak mengelola akun berizin lebih tinggi) ditegakkan server dan ada di adapter contoh. Akun berperan Ubah wajib 2FA; tulis lewat publik mati bawaan.
- Nilai bawaan pengaturan dan peran satu sumber di `lib/defaults.ts` (`DEFAULT_SETTINGS`, `DEFAULT_ROLES`); tabelnya ada di ADR 0006. Ubah di sana, bukan di UI.
- Adapter contoh (`lib/data/mock.ts`) memuat akun dan kode demo untuk mencoba alur; **jangan ikut build rilis**. Di mode contoh, drawer Appearance memuat pilihan pratinjau desktop/jarak jauh. Tidak ada saklar desktop/mobile di header: tata letak mengikuti lebar layar.
- **Dua bahasa** (ADR 0008): jangan menulis teks tampilan mentah. Di komponen `const t = useT()`; kunci = teks Indonesia persis (`t("Tambah user")`); sisipan `{n}`; jamak English `"{n} user|{n} users"` di kamus. Konstanta modul memakai `tk("...")` lalu `t(label)` saat render. Kamus: `src/lib/i18n/en/<area>.ts`. `bun run i18n:check` wajib bersih (teks belum dibungkus, kunci hilang, placeholder tidak sama, kunci ganda berbeda); beri `// i18n-ignore: alasan` hanya untuk label berkunci `tk` atau pesan developer.
- **AI chat** (ADR 0007): hanya membaca; izin "AI chat" per peran + izin menu datanya; panel di `components/ai-chat-*.tsx`, status di `lib/ai-provider.tsx`, mesin contoh di `lib/data/ai-engine.ts` (jawaban = teks + widget + aksi + saran + sumber + langkah). Riwayat lewat `api.*AiChat` (data Telemon per akun, bukan browser). Desktop: tombol melayang dan panel menempel di kanan (mendorong halaman); HP: tombol AI di ujung kanan menu bawah, layar penuh. Pintasan: Alt+A, `/` perintah cepat.
- **Backend AI** (ADR 0024): crate `crates/telemon-ai` (klien `Llm` untuk OpenAI-compatible dan Anthropic, enam alat baca di `tools.rs` yang menegakkan izin per alat, loop di `agent.rs`, layanan di `service.rs`); penyimpanan di `telemon-core/src/aistore.rs`; rute `/api/ai/*` di `telemon-http/src/ai.rs` (jawaban NDJSON). **Alat AI tidak boleh punya jalur tulis**, tidak boleh memuat password atau komentar bebas, dan IP/MAC disamarkan bawaan. Kunci API hanya di `SecretStore`. URL dasar kustom hanya boleh diatur dari desktop (SSRF). Server demo memakai model offline `demo_llm.rs`.
- **Analitik dan usulan tata letak AI** (ADR 0027): alat baca tambahan di `telemon-ai/src/analytics.rs` (`event_stats` memakai agregasi SQL `Store::event_timeline/event_top_users/event_counts_by_router`, bukan `list_events` yang dibatasi 500 baris; `bandwidth_summary`; `router_health`) dan `layout.rs` (`get_layout`, `propose_layout_change`). `propose_layout_change` **tidak menulis**: memvalidasi usulan terhadap `UiContext` (widget dan katalog jenis yang dikirim klien bersama pertanyaan, divalidasi ukuran/bentuknya di `UiContext::validate`) dan izin Ubah Ringkasan penanya, lalu mengembalikan widget `Proposal { ops }`; nama router diganti id. UI menampilkan `components/ai-proposal.tsx`; **Terapkan** menyimpan lewat `api.saveDashboard` dengan izin pengguna sendiri setelah `applyLayoutOps` (`components/dashboard/ops.ts`) memeriksa ulang (semua-atau-tidak-sama-sekali), lalu `notifyDashboardChanged()` memuat ulang Ringkasan. Status `applied`/`dismissed` disimpan di widget (kolom `state`) ke riwayat. Jenis widget dan kunci pengaturannya ada di UI (`configKeys` di registry); `layout.rs` menyalin kunci tiga widget bandwidth: ubah keduanya bersamaan. Model demo (`demo_llm.rs`) dan mesin mode contoh (`ai-engine.ts`) punya jalur yang sama untuk dicoba.
- **Loading dan daftar panjang**: loading memakai shimmer (`components/ui/skeleton.tsx`, `components/skeletons.tsx`); daftar panjang memakai scroll tanpa henti (`hooks/use-infinite-list.ts` + `LoadMore`), jangan tombol "Tampilkan lagi".
- **HP**: menu Berbagi/Admin/Pengaturan ada di **modal** Profile (`components/account-menu.tsx`), bukan dropdown; menu bawah hanya menu utama + tombol AI.
- Dev dari HP/laptop lain: `bun run dev --host`.
- **HP: halaman, bukan drawer/dialog** untuk detail dan formulir (detail user, tambah/edit user, profil PPP, router, import, akun, peran, Appearance). Rute bertingkat di hash: `#/user/new`, `#/user/<id>`, `#/user/<id>/edit`, `#/profile/new|<id>/edit`, `#/router/new|<id>/edit`, `#/import`, `#/appearance`, `#/admin/account/new|<id>/role|<id>/password`, `#/admin/role/new|<id>/edit` (`lib/route.ts`: `pathHref`, `navigatePath`). Satu formulir melayani dua tata letak lewat `components/form-layout.tsx` (`FormLayoutProvider`, `FormHeader`, `FormFooter`); pembungkus halaman di `pages/subpages.tsx`, perutean di `App.tsx` (`renderPage`). Desktop tetap dialog/drawer (`useIsDesktop`). Formulir baru: buat komponen `XForm` dengan `FormHeader/FormFooter`, pakai di dialog dan di subpages.
- **Dasbor AI** (`components/ai-dashboard.tsx`, bagian Pengaturan): provider, saldo, token, biaya, anggaran. Kunci API write-only (hanya `keyHint`); API `getAiDashboard`, `saveAiProvider`, `testAiProvider`, `setDefaultAiProvider`, `removeAiProvider`, `saveAiBudget`. Form provider: `components/ai-provider-dialog.tsx` (dialog di desktop, `#/pengaturan/ai-provider/...` di HP). Grafik memakai warna `brand`, status memakai ikon + label; tersedia tampilan tabel.
- **Ringkasan = widget** (ADR 0025): satu tata letak global untuk semua akun, disimpan di server (`GET/PUT /api/dashboard`, `layout: null` = bawaan; bentuk divalidasi di `crates/telemon-http/src/dashboard.rs`). Izin **Ringkasan Ubah** = boleh mengatur widget (Administrator bawaan; admin lama dimigrasi satu kali). Jenis widget ada di UI: `components/dashboard/registry.tsx` (`WIDGETS`: judul `tk`, ukuran awal, `resizable` false = kartu angka berukuran tetap, `tile` = dua per baris di HP); susunan bawaan = tampilan lama di `lib/dashboard.ts` (`DEFAULT_WIDGETS`, grid 20 kolom, **baris 4 px tanpa jarak vertikal grid**; jarak antar widget = `WIDGET_GAP` 8 px sebagai padding bawah di dalam widget, jadi tinggi terlihat = 4h - 8 px). Widget yang tingginya mengikuti isi (`autoHeight`, kini kartu router) mengukur dirinya lewat `useAutoHeight` dan grid memakai `rowsForHeight`; hanya lebarnya yang bisa diubah. Grid memakai `react-grid-layout` (`components/dashboard/grid.tsx`); mode ubah hanya md ke atas, HP satu kolom menurut urutan baca (`DashboardStack`). Widget baru: tambah komponen + entri `WIDGETS` + kamus `i18n/en/dashboard.ts`; jenis tak dikenal dibuang UI saat memuat. Metode `getDashboard`/`saveDashboard` ada di kedua adapter.
- **Bandwidth** (ADR 0026): pengumpul per router (`telemon-core/src/traffic.rs` menghitung laju dari selisih counter `/interface`, tugas `run_traffic` di `monitor.rs`, tabel `traffic_samples`/`traffic_ifaces` lewat `trafficstore.rs`). Pengaturan `bandwidth` (aktif, interval 10-3600 dtk, simpan 1-365 hari) di `settings.rs` dan `lib/defaults.ts` (ubah keduanya); `RuntimeConfig.traffic` None = pengumpul mati. Antarmuka PPPoE dinamis (`pppoe-in`) **tidak** dicatat satu per satu: dijumlah menjadi antarmuka virtual `@pppoe` + jumlah sesi; hanya itu yang boleh dijumlah lintas router (`router=all`), antarmuka fisik akan terhitung ganda. Arah mengikuti router: untuk PPPoE `tx` = unduhan pelanggan (`lib/traffic.ts` `directions`). API `GET /api/traffic/interfaces|series` (izin Router Lihat, `crates/telemon-http/src/traffic.rs`). Widget di `components/dashboard/bandwidth-widgets.tsx` (pengaturan per widget lewat `Config` di registry, tersimpan di `config` tata letak); grafik SVG sendiri `traffic-chart.tsx`, dua deret dibedakan solid vs putus-putus. Server demo mensimulasikan antarmuka dan mengisi riwayat 24 jam. Metode `getTrafficInterfaces`/`getTrafficSeries` ada di kedua adapter.
- **Menu aksi baris** (`components/action-menu.tsx`: `ActionMenu*`, API sama dengan DropdownMenu): dropdown di desktop, lembar bawah di HP. Pakai ini, bukan `DropdownMenu` langsung, untuk menu aksi baris/kartu. **AI chat di HP = halaman `#/ai`** (`AiChatPage` di `ai-chat-dock.tsx`; `open` di `ai-provider.tsx` mengikuti rute di HP, state lokal di desktop).
- **Core Rust ringan** (ADR 0010): tanpa OpenSSL/aws-lc (rustls + ring), SQLite statis satu-satunya pustaka C, profil rilis `opt-level = "z"` + LTO + strip.
- **`crates/telemon-core`** (crate Rust murni, tanpa SQLite/Tauri): model PPP (`PppActive`, `PppSecret` dengan password disembunyikan di `Debug`, `PppProfile`) dan klien RouterOS (`RouterApi`, `MikrotikClient` memakai `mikrotik-rs`, ADR 0011). Diuji dengan router tiruan di `router.rs` (protokol kalimat RouterOS). Poller dan deteksi event (ADR 0012): `Detector` (selisih sesi + log), `poll_once`, `run_poller`, `user_status`. Penyimpanan SQLite (`store.rs`, ADR 0013): event, sinkronisasi user/profile, catatan lokal, retensi. Pemantau (`monitor.rs`): `run_router` (sinkronisasi + polling -> event tersimpan + status user live), `run_purge`, store dibagi `Arc<Mutex<Store>>`. Tulis ke router (`write.rs`, ADR 0014): `plan_*` -> tinjau `Plan::changes` -> `apply` (hanya perintah di `ALLOWED`; tanpa `remove` secret/profile), lalu `sync_router`. Gunakan `apply_audited` agar setiap penerapan tercatat di tabel `audit` (`list_audit`, retensi `auditDays`). Password terenkripsi (`vault.rs`, ADR 0009): `Store::unlock(kunci 32 byte dari keyring OS)` wajib sebelum password disimpan/dibaca; `user_password` terpisah dari `list_users`; jangan pernah mencatat password. TLS api-ssl (`tls.rs`, ADR 0015, fitur `tls` bawaan): `MikrotikClient::connect_with(.., TlsMode::Pinned(sidik jari))`, `fetch_fingerprint` untuk percaya-saat-pertama (tampilkan ke pengguna dulu); `api-ssl` router harus punya sertifikat. Router (`store.rs`: `add_router`, `update_router`, `remove_router`, `RouterRecord::tls_mode`): metadata + `tls_pin` di SQLite, **kata sandi API di keyring OS (`router:<id>`)**, hapus router tidak menghapus riwayat perubahan; status router diperbarui otomatis oleh `run_router`. Belum ada: sambungan ke aplikasi Tauri (termasuk kunci enkripsi dan kata sandi router dari keyring), riwayat login/akun/peran/pengaturan (fitur `tls` + rustls/ring), password terenkripsi, riwayat perubahan.
- **Lapisan service** (`service.rs`, ADR 0016): aplikasi hanya memanggil `Telemon<C: Connector>` (kelola router + kredensial lewat `SecretStore`, `probe`, `start_monitor`/`shutdown`, `subscribe` event, `plan_*` -> `apply`, `import_now`, purge). Jangan memanggil klien/penyimpanan langsung dari UI atau command. Uji dengan `FakeConnector`/`MemorySecrets`.
- **Server akun** (`auth.rs`, ADR 0017): `Auth` memegang akun, peran, sesi, 2FA. Semua metode sinkron (argon2): panggil dari `spawn_blocking`. `caller: Option<&Session>`, `None` = desktop. Penegakan izin selalu lewat `authorize` dan guard di `create_account`/`update_role`/dst; jangan membandingkan izin sendiri. Galat memakai `AuthError::code()`. Rahasia (password, token, kode 2FA) tidak pernah masuk riwayat.
- **Server HTTP** (`crates/telemon-http`, ADR 0018): `app(state)` = API JSON + UI statis; semua rute memanggil `Auth::authorize`, jangan menambah rute tanpa pemeriksaan izin dan uji di `tests/http.rs`. Tulis ke router hanya lewat rencana yang disimpan di server (`planId`), tidak pernah menerima langkah dari klien. Jangan memasukkan password pelanggan/kata sandi router ke DTO. Jalan: `cd crates/telemon-http && cargo test`. Kontrak JSON mengikuti `src/lib/types.ts` (camelCase).
- **Pengaturan** (`settings.rs`): satu sumber nilai bawaan dan rentang di core (cermin `src/lib/defaults.ts`; ubah keduanya bersamaan). `AppState::reload_settings`/`set_share` menerapkan ke kebijakan akun; `Telemon::apply_settings` ke pemantau. Izin tulis lewat publik hanya dari desktop.
- **Sumber data UI** (`lib/api-provider.tsx`, ADR 0019): di browser, bila `/api/health` menjawab, UI memakai `HttpApi` (`lib/data/http.ts`); selain itu data contoh (`?mock` memaksa). Setiap metode baru di `TelemonApi` wajib ada di **kedua** adapter (mock dan HTTP) dan di server; metode yang belum didukung server mengembalikan promise yang **ditolak** `ApiError` 501 (jangan melempar sinkron). Kolom `null` dari server dibuang oleh adapter (kecuali pengaturan).
- **Server demo** untuk mencoba UI dengan data dari server sungguhan: `bun run build`, lalu `cd crates/telemon-demo && cargo build --release` dan `./target/release/telemon-demo --static ../../dist [--bind 0.0.0.0 --port 5173]`. Hanya untuk pengembangan (data tiruan, kata sandi `demo-telemon`). Akun `pantau` memakai peran demo **Monitor Plus** (Ringkasan Ubah, Event/Router Lihat, Pengaturan Ubah, AI chat) dan demo mematikan 2FA untuk peran berizin Ubah lewat `HttpConfig::relax_update_2fa` (`AuthPolicy::update_roles_need_2fa`, bawaan true); saklar Wajib 2FA dan akses Publik tetap memaksa. Jangan memakai saklar itu di luar demo.
- Dev UI terhadap server: `VITE_TELEMON_URL=http://127.0.0.1:7878 bun run dev` meneruskan `/api` (termasuk WebSocket) ke server.
- **Rilis** (`.github/workflows/release.yml`, ADR 0020): runner Linux untuk Linux dan Windows (cross-compile cargo-xwin + NSIS), runner `macos-15` untuk macOS (universal, ad-hoc, tanpa notarisasi). Versi dari tag lewat `.github/scripts/set-version.py` (jangan edit versi manual untuk rilis). Action pihak ketiga dikunci SHA (perbarui lewat `gh api repos/<action>/git/ref/tags/<tag>`); cache hanya disimpan dari run branch, jadi hangatkan dengan `workflow_dispatch` tanpa tag setelah lockfile berubah. Perubahan workflow belum bisa diuji dari olympus: uji lewat dispatch.
- **Aplikasi desktop** (ADR 0021): webview ke server loopback bertoken (`crates/telemon-desktop` + `src-tauri`); tidak ada command Tauri untuk data, UI memakai `HttpApi`. Logika desktop ditaruh di `telemon-desktop` agar teruji tanpa Tauri (`cargo test`, biner `telemon-headless --data DIR --static dist`); `src-tauri` tetap tipis. Pengaturan Berbagi (`/api/share*`) hanya permukaan Desktop. Kunci baru tidak boleh disimpan sebelum cocok dengan basis data. Dev: `bun run tauri dev` (Vite meneruskan /api ke 127.0.0.1:47831).
- **Akses Publik** (ADR 0022): `cloudflared` resmi diunduh otomatis ke `<data>/bin` dengan versi + SHA-256 terkunci (`telemon-desktop/src/cloudflared.rs`, `pin_for`); memperbarui versi = mengganti pin dari `digest` aset rilis GitHub. Mesin status di `telemon-http/src/share.rs` (`Tunnel` trait; uji dengan `FakeTunnel`). Jangan mengemas biner di installer. Uji nyata (butuh internet): jalankan `telemon-headless`, nyalakan Serve lalu Publik lewat `/api/share/*`.
- **Pembaruan aplikasi** (ADR 0023): updater dipanggil dari Rust dan dipaparkan lewat `/api/update*` (permukaan Desktop saja); jangan membuka IPC Tauri ke webview. Cadangan basis data wajib sebelum pasang (`Store::backup_to`). Rilis: berkas ditandatangani (secret `TAURI_SIGNING_PRIVATE_KEY*`), `.github/scripts/make-latest-json.py` membuat manifest dan gagal keras bila tidak lengkap; rilis `channel-rc` hanya pembawa manifest kanal uji (workflow mengabaikannya). Kunci publik di `src-tauri/tauri.conf.json`; mengganti kunci butuh versi jembatan. Repo ini **publik**: jangan commit rahasia.
- **Extension** (ADR 0028, prototipe 1: hanya tingkat **official**, hanya widget Ringkasan; paket extension ada di **repo terpisah**). Crate `crates/telemon-ext` (murni): `manifest.rs`, `package.rs` (berkas `.tmx` = zip dengan `manifest.json`, `ui/*`, `signature.json`; tanda tangan Ed25519 atas ringkasan SHA-256 semua isi; batas ukuran dan jalur aman; tingkat ditentukan kunci penanda tangan; `apiVersion` 1) dan biner `tmx` (`keygen`, `pubkey`, `pack`). Penyimpanan: tabel `extensions` dan `extension_perms` (`Store::ext_*`). Server: `telemon-http/src/extensions.rs` (`/api/extensions` daftar, `inspect`, pasang, `PATCH` aktif/izin, `DELETE`, `/api/extensions/active` untuk UI, `/ext/{id}/ui/*` hanya untuk yang aktif dan official). Kelola = izin **Admin** (Lihat untuk daftar, Ubah selebihnya; Ubah wajib 2FA dan tidak lewat Publik); semua perubahan masuk riwayat audit. Saklar: `HttpConfig.extensions` (`ExtConfig::from_env`): desktop aktif bawaan, server/image mati sampai `TELEMON_EXTENSIONS=1`; `TELEMON_EXTENSIONS_DIR`, `TELEMON_EXTENSIONS_OFFICIAL_KEYS` (kunci official tambahan, hanya pemilik server), `TELEMON_EXTENSIONS_ALLOW_UNSIGNED` (hanya pengembangan). `OFFICIAL_KEYS` di `state.rs` **masih kosong sampai kunci Teliti dibuat** (simpan seperti kunci updater). Izin extension: toggle per izin, sensitif mulai mati, izin baru saat pembaruan mati, izin wajib mati = status `limited` (tidak dimuat). UI: kontrak di `src/lib/extensions/sdk.ts` (modul `ui/index.js` mengekspor `{ activate(sdk) }`, React milik aplikasi lewat `sdk.React`), pemuat `lib/extensions/loader.tsx`, registri `lib/extensions/registry.ts` (jenis widget `ext:<id>:<jenis>`, dimasukkan ke `WIDGETS`), halaman `pages/settings-extensions.tsx` (`#/pengaturan/extension`). Kode UI extension official berjalan dengan sesi pengguna (bukan sandbox). Belum: tingkat public, WASM/worker/API extension, slot menu dan detail, sumber pasang tautan dan toko official, mode aman `?ext=off`; widget extension yang sedang mati hilang dari tata letak bila tata letak disimpan saat itu.
- **Kompatibilitas extension** (ADR 0028): manifest `telemon` (rentang versi Telemon) dan `requires` (`id`, rentang, `optional`); `telemon-ext/src/version.rs` (`Version`, `Range`: `>= > <= < = ^ ~ *`, praterbit diabaikan), `resolve.rs` (`check_install`, `dep_status`, `dependents_of`, `host_compatible`, `install_order`). API: inspect mengembalikan `problems`/`requires`; pasang ditolak 409 `incompatible`; hapus ditolak 409 `has_dependents`; status `limited` bila syarat wajib mati/tak cocok, `incompatible` bila versi Telemon (`HttpConfig.host_version`) keluar rentang saat dimuat. Pemasangan otomatis dependensi menunggu toko. Belum: halaman Akses per extension, dasbor per extension, migrasi database (hanya desain di ADR 0028).
